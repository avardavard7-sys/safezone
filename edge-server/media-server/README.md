# SafeZone LIVE — сервер видео

Непрерывное видео с камер в панели с задержкой около секунды. Камеры не
трогаем: сервер сам забирает поток, браузер получает его по WebRTC.

```
камеры ─RTSP─► MediaMTX ─WebRTC─► браузер
                  │
                  └─RTSP (локально)─► бридж: ИИ-анализ
```

У камеры одно подключение на всех — и зрители, и анализ читают один поток.
Поток с камеры тянется только пока кто-то смотрит или анализирует; через
15 секунд тишины отпускается.

## Что нужно

- VPS на Ubuntu 22.04 или 24.04 с публичным IP, Docker с compose
- домен или поддомен, A-запись на этот сервер — нужен для HTTPS
- доступ сервера к камерам: туннель от коробки SafeZone или прямая сеть

## Установка

```bash
cd edge-server/media-server
cp ../bridge/.env bridge.env      # обычные настройки бриджа: Supabase, ключи ИИ
./setup.sh                        # домен, ключи, секрет, файрвол
docker compose up -d --build
docker compose logs -f bridge     # ждём «LIVE: ✓ MediaMTX»
```

`setup.sh` напечатает две переменные — их в Vercel, затем передеплоить панель:

```
MEDIA_PUBLIC_URL=https://media.твой-домен
MEDIA_JWT_PRIVATE_KEY=-----BEGIN PRIVATE KEY-----\n...
```

Без них панель показывает снимки с меткой «СНИМОК» — ничего не ломается.

## Кто что может

| Кто | Протокол | Откуда | Как |
|---|---|---|---|
| Зритель | WebRTC | откуда угодно | токен на одну камеру, живёт 2 минуты |
| Бридж | RTSP | только с этого сервера | короткий секрет из `bridge.env` |
| API MediaMTX | HTTP | только с этого сервера | — |
| Публикация | любой | — | запрещена всем |

Токен выдаёт панель после проверки входа и прав на камеру (RLS). Решение о
доступе MediaMTX каждый раз спрашивает у бриджа — отозвать доступ можно
мгновенно, без перезапуска.

## Порты

| Порт | Что | Наружу |
|---|---|---|
| 443/tcp, 80/tcp | HTTPS (Caddy, сертификат сам) | да |
| 8189/udp, 8189/tcp | медиа WebRTC; TCP — если у зрителя закрыт UDP | да |
| 51820/udp | WireGuard от коробок | да |
| 8554, 8889, 9997, 8099 | RTSP, сигнализация, API, бридж | только 127.0.0.1 |

## Камеры

- кодек **H.264**: H.265 в браузерах работает не везде
- **без B-кадров**
- **ключевой кадр раз в 1–2 секунды** — иначе плеер ждёт его по 4–8 секунд
- в сетке лучше дополнительный поток (`subtype=1` у Dahua/Imou)

## Проверка

```bash
curl -s http://127.0.0.1:8099/health            # бридж жив
docker compose logs mediamtx | grep -E "ERR|started"
```

В панели у камеры должна загореться зелёная метка **LIVE**. Она горит, только
когда в браузере реально декодируются кадры.

## Если не показывает

| Метка | Причина |
|---|---|
| СНИМОК | в Vercel нет `MEDIA_PUBLIC_URL` / `MEDIA_JWT_PRIVATE_KEY` |
| НЕТ ДОСТУПА | ключ в Vercel не от той пары — запусти `./setup.sh` ещё раз и вставь ключ, который он напечатает: пара сохраняется, не меняется |
| ПЕРЕПОДКЛЮЧЕНИЕ | закрыт 8189 или нет связи с камерой — `docker compose logs mediamtx` |
| НЕТ СИГНАЛА | камера не отдаёт поток или кодек H.265 |
