# SafeZone — весь проект в одной папке

Две части, которые работают в паре.

```
корень/          Панель — Next.js, живёт на Vercel в облаке
edge-server/     Бридж — Docker, живёт на компьютере внутри объекта
```

Панель в облаке физически не видит камеры в локальной сети объекта. Поэтому
камеры смотрит бридж на месте, а в облако уходит только результат.

---

## Панель (корень)

Next.js 14 + Supabase. Деплоится на Vercel автоматически после пуша в `main`.

**Страницы:** дашборд, камеры, мониторинг, события, зоны, редактор зон, бридж,
арендаторы, нарушения, аналитика, функции, разработчик, настройки, AI-демо.

```bash
npm install
npm run dev          # http://localhost:3000
npx tsc --noEmit     # проверка типов
npm run build        # сборка
```

Переменные — в `.env.local` (в гит не уезжает):

```
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
NEXT_PUBLIC_BRIDGE_API=http://127.0.0.1:8099
```

---

## Бридж (`edge-server/`)

Версия **7.12**. Подробности по каждой версии — `edge-server/README-V7.md`.

Смотрит RTSP-потоки, локально фильтрует кадры детектором и скелетами, в облако
обращается только когда есть повод. Правила зон считает сам, без облака вообще.

**Установка на объекте:**

1. Панель → **Бридж** → «Добавить бридж» → код из 8 символов (живёт 24 часа)
2. В `edge-server/bridge/.env` вписать `PAIRING_CODE=XXXXXXXX`
3. В папке `edge-server/`:

```bash
docker compose up -d --build
docker compose logs -f bridge      # ждём «Привязан к объекту»
```

Дальше терминал не нужен: стоит `restart: unless-stopped`, бридж поднимается
сам после перезагрузки. Всё управление — из панели.

**Состояние привязки** — `edge-server/bridge/data/state.json`. Не удалять:
пароль сервис-аккаунта выдаётся только при первой привязке. Потерял файл —
удали бридж в панели и создай новый код.

**Тесты:**

```bash
cd edge-server/bridge
node test-pairing.mjs    # 22 теста привязки, без сети и без ONNX
node test-local.mjs      # 169 тестов: трекер, серии кадров, зоны, детектор
```

## База

Supabase, проект `cejwgfwmyzofnezqwbgu`. Все миграции уже применены к боевой
базе — файлы в корне (`database_migration_*.sql`) и в `edge-server/`
(`MIGRATION-*.sql`) лежат для истории и для разворачивания с нуля.

RLS включён на всех таблицах. Бридж ходит под собственной учётной записью с
ролью `security`, ограниченной своим объектом.

## Модели детектора

В `edge-server/bridge/` лежат 5 файлов `.onnx` (~150 МБ суммарно). Они нужны
для работы и включены в архив.

Если не хочется держать их в репозитории — добавь `*.onnx` в `.gitignore`,
а на месте скачай скриптом `download-phase1-models.ps1` (Windows) или
`download-phase1-models.sh`.
